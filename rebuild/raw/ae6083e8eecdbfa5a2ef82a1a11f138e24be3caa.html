Swinging project data

Swinging project data are project data that change unpredictably due to a renewed update of the extension points.

A possible error cause is a selection formula for an extension point that does not supply a unique result. After the extension points have been updated for the first time, project components are mounted in an indefinite order on the extension points and the formula result is cached. During the second update of the extension points, the formula result from the cache is used. However, a deviating result is achieved by the changed initial situation.

A further error cause is a selection formula for an extension point with a reference to a parameter value that changes when the extension point is updated.

Example 1

The modular system consists of the mechatronics components MainComponent, A, B, C, AA, BB and CC, as well as the parameters test and the interfaces ILevel1 and ILevel2.

The test parameter of the Boolean type is integrated into the components MainComponent, A, B and C.

In the MainComponent component, the test parameter has the value =mos.first.isInstanceOf('Swinging.Components.B').ifEmptyNullOrError(false).

In components A, B, and C, the test parameter has the value =mc.$test.

The components A, B and C implement the interface ILEVEL1 and the components AA, BB and CC implement the interface ILEVEL2.

The MainComponent component has an extension point to install two components each that implement the ILevel1 interface.

The components A, B and C each have an extension point to install one component each that implements the ILevel2 interface.

Random project data after the first update of the extension points:

The project data includes only the root component MainComponent and two instances each of A, B and C.

Random project data after the second update of the extension points:

This time the project data includes the root component MainComponent, two instances each of A, B and C and one instance each of AA, BB and CC.

Remedy

  • Only instances of the same modular system component should be built into an extension point. In the example presented, therefore, three extension points should better be present in the root component, one each for instances of A, for instances of B and for instances of C.
  • The selection formula collects all instances with mos that are listed in an unpredictable sequence. The sortedBy(x|x.name) method can be used to sort the entries in the list alphabetically so that the same order is always created for an identical number of collected instances.

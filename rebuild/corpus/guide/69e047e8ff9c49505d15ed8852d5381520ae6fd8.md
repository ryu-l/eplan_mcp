# Reorganizing Projects

When you reorganize a project, then deleted data is irretrievably removed from the project database. The project database is reduced in size.

![](../Pictures/Gui/ALL/note.png)Note:

We recommend that you make a backup copy of the project before reorganizing since this action affects the entire project database.

Precondition:

You have selected a project in the page navigator.

1. Select the following commands: File > Extras > Command group Organize > Project > Command group Optimize > Compress project.
2. Click [...] next to the Settings field in the Compress project dialog.
3. In the Settings: Compression dialog, select the scheme you want to edit or create a new one.
4. In the field Data to be compressed activate the check box Reorganize project and keep the check box Advanced mode deselected.
5. Click ![](../Pictures/Gui/ALL/all_save_as.png) (Save).
6. Click [OK].  
     
   ![](../Pictures/Gui/ALL/arrow.png) The project is reorganized.

### Correct project data structures

For reorganization, an advanced mode is available. This mode allows for automatic correction of field length excesses in the project database as well as for internal checks of the sorting IDs of the project structure and their automatic correction, if necessary.

Field length excesses can result from entering very long identifiers, numbers, and designations. the cause for this being that most database fields of the project database have a length limit. A field length excess can lead to truncating the entered data. This may lead to incorrect results.

1. To open the Settings: Compression dialog proceed as described above under "Reorganizing Projects".
2. In the field Data to be compressed select the check box Advanced mode below the check box Reorganize project.
3. Confirm your entries.  
     
   ![](../Pictures/Gui/ALL/arrow.png) The project is reorganized.  
     
   ![](../Pictures/Gui/ALL/arrow.png) Parts that exist double in the project are removed. The connections are deleted and subsequently generated again and optimized.  
     
   ![](../Pictures/Gui/ALL/arrow.png) In addition, the project database is searched for field length excesses. If a field length excess is discovered, the database is restructured so that the field length of the respective database field is adjusted in accordance with the entered data length (plus a 10 percent reserve). Then, the new field length is stored in the project.

![](../Pictures/Gui/ALL/info.png)Tip:

You can also reorganize projects that can no longer be opened in Eplan by using the action Manage project ([projectmanagement](availableactions_o_projectmanagement.htm)) and specifying the parameter "/TYPE: REORGANIZE". This allows projects with database errors to be repaired in many cases and then opened again. This action is available when customizing the ribbon.

# Spare Items: Function templates

Device definitions (types) are the central elements for working with [devices](Glossary_o_betriebsmittel.htm); they consist of a list with elements, the so-called [function templates](Glossary_o_funktionsschablonen.htm) that contain a large number of minimal identifying function [properties](Glossary_o_eigenschaften.htm).

The following properties are available for function templates:

- Function definition
- Connection point designation (e.g. 13Pi14)
- Terminal designation (e.g. 001)
- Index 1 (e.g. 0-9, etc.)
- Index 2 (e.g. 0-9, etc.)
- Technical characteristics (e.g. 400V).

### Overlay and overwriting behavior of functions and function templates

When overlaying properties, the following should be noted: If a template property contains a value, then the function must have exactly the same value in order to be overlaid by the function template. If the function contains an empty property, then the function only fits function templates that also have this property empty! However, empty function template properties match any function values.

This behavior can be illustrated by the following example:

|  | Template Fn. def.: Terminal Terminal designation: PE Level: empty | Template Fn. def.: Terminal Terminal designation: PE Level: 2 | Template Fn. def.: Terminal Terminal designation: PE Level: 3 |
| --- | --- | --- | --- |
| Function  Fn. def.: Terminal Terminal designation: PE Level: empty | Match | Do not match | Do not match |
| Function  Fn. def.: Terminal Terminal designation: PE Level: 2 | Match | Match | Do not match |
| Function  Fn. def.: Terminal Terminal designation: PE Level: 3 | Match | Do not match | Match |

When Overwriting properties (e.g. when choosing devices), the following should be noted: If a property of a template contains a value, then this value is also adopted by the function; if a property of a template is empty then the respective property of the function remains unchanged when overwritten!

### Special characteristic of cables / cable connections

The potential type of [connections](Glossary_o_verbindungen.htm) is handled differently to the procedure described above. In this case: If the template or function has the potential type "PE", "PEN" or "SH", the counterpart must also have exactly this potential type.

If the potential type of the template or function is neither "PE" / "PEN" nor "SH", the template and function always match, even when the potential type is not identical.

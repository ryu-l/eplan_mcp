# Revisioning Defined Working Sections

The Change tracking function can be used to revision sections of a project. The sections to be revisioned are defined through the defined working sections. Changes in the individual defined working sections are documented and protected independently of each other. This is only possible if the defined working sections do not overlap. When you complete a defined working section, the associated pages or layout spaces have an automatic change protection assigned to them.

Revisioning of defined working sections is carried out page-by-page. This means that you have to use [properties](Glossary_o_eigenschaften.htm) for [structure identifiers](Glossary_o_strukturkennzeichen.htm) (for example Higher-level function and mounting location) or page properties (for example Page name) as filter criteria when defining defined working sections. This allows sections of a [project structure](Glossary_o_projektstruktur.htm) or individual [trades](Glossary_o_gewerke.htm) to be revisioned separately. In order to revision trades the project has to be structured so that all the pages of a trade are allocated uniquely to a specific page structure.

You have defined the fluid-specific pages of a project as a defined working section, revisioned it and completed it. This means that these pages have a change protection. The multi-line pages of a different defined working section contain electrical engineering [functions](Glossary_o_funktionen.htm) that are linked by means of [pair cross-references](Glossary_o_paarquerverweise.htm) with their counterpieces on the fluid-specific pages. You can still edit these electrical engineering functions. These changes are recorded during the revisioning of the electrical engineering section.

The revision data of the defined working sections are displayed in the page properties and in the Edit revision data dialog and are output in the revision overviews.

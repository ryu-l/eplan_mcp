# Behavior of Graphical and External Functions

For graphical and external [functions](Glossary_o_funktionen.htm), [connections](Glossary_o_verbindungen.htm), and cables, the following applies:

- They are not shown in the [navigators](Glossary_o_navigatoren.htm).
- They cannot be returned, that is, it is not possible to delete only the placement.
- They are not cross-referenced (either with logical functions or between each other).
- They are not taken into account in test runs.
- They are not taken into account when automatically generating cables.
- They are not taken into account for [connection numbering](Glossary_o_verbindungsnummerierung.htm).

### Reports

In [reports](Glossary_o_auswertungen.htm), a distinction is made between target specifications and direct evaluation of [objects](Glossary_o_objekte.htm).

#### Target specifications

Targets are only evaluated via logical and external connections, but not via graphical connections. This means that whether a target is output in a report does not depend on the target itself, but on the connection to that target. If the connection to the target is graphical, then the target will not be reported. If the connection to the target is external, the target is not evaluated and reported.  
In contrast to logical connections, external connections are not directly reported, that is, they are included, for example, in terminal plans but not in connection lists. Graphical connections are not evaluated and reported.

#### Direct evaluation of objects

Graphical and external functions are not output in reports (except as targets). This also applies to graphical and external connections and cables.

Parts on external and graphical components or connections are not included.

### DT adoption and structure identifiers

DT adoption is independent of the representation type and for graphical and external functions acts just the same as for logical functions. Adopting [connection point designations](Glossary_o_anschlussbezeichnungen.htm) also works for graphical components.

Structure identifiers which only exist on graphical functions, however, are not visible in [structure identifier management](Glossary_o_strukturkennzeichen_verwaltung.htm).

A structure identifier entered in a graphical function is also not entered in the structure identifier database. If a logical [component](Glossary_o_schaltzeichen.htm) adopts the DT of a graphical or external component, then the corresponding [structure identifiers](Glossary_o_strukturkennzeichen.htm) are then added to structure identifier management.

If structure identifiers are changed in structure identifier management, then the entries are also changed on graphical or external components.

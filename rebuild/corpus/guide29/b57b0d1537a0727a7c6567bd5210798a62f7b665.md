# Editing Projects in Multi-user Operation

In EPLAN it is possible to work simultaneously over a network on one project with multiple users from different [stations](Glossary_o_stationen.htm). Conflicts can arise in this so-called [multi-user operation](Glossary_o_multiuser_betrieb.htm), for example, if multiple users want to edit the same data. If a conflict arises, the users will be notified with a message dialog.

### Messages if a conflict occurs

If you want to edit [project data](Glossary_o_projektdaten.htm) that is already being edited by another user, EPLAN informs you with a [Multi-user conflict](xesmultiuserconflictgui_d_konflikte.htm) dialog that editing is not possible.

In this dialog, all users currently editing the same data are listed with name, telephone number, e-mail address, and workstation name. This information allows you to contact the user(s) by telephone or e-mail and ask them to either release the data being used or inform you when they have finished editing.

The conflict situation described above does not mean that you can't see the data, but rather that the data is locked by the other user from editing. After closing the Multi-user conflict dialog, the corresponding [properties](Glossary_o_eigenschaften.htm) dialog will open in EPLAN for you to view.

As soon as the first user has completed work, the data is released again for other users. You can see the changed data after refreshing it with [F5]. This will also re-release the fields of an open properties dialog.

![](../Pictures/Gui/ALL/note.png)Notes:

- Please note that for multi-user operation the project must be opened in the "Default" processing mode. If you open a project in the "Exclusive" mode, the other users cannot access this project any more.
- The Multi-user conflict dialog only makes sense if all of the users in multi-user operation have stored their user information in the [settings](Glossary_o_einstellungen.htm) (Options > Settings > User > Display > User code / address).

### Project-wide editing in multi-user operation

For some operations where project data is to be changed across the entire project, only one user (exclusively) is allowed to access the project. This could be for the following [actions](Glossary_o_aktionen.htm):

- A user is editing the [project properties](Glossary_o_projekteigenschaften.htm).
- A user is making changes in a [layout space](Glossary_o_bauraum.htm).
- A user has opened [structure identifier management](Glossary_o_strukturkennzeichen_verwaltung.htm) for a project.
- The project is being compressed, saved, or restored by another user.
- A user is synchronizing [master data](Glossary_o_stammdaten.htm) in a project, which means that all master data references in the project change.

In these cases, EPLAN can't open the project in question for multi-user operation and, via the conflict dialog, informs the other users who would like to open the project as to which user is currently accessing it.

![](../Pictures/Gui/ALL/note.png)Note:

If several users have opened the same project in multi-user operation, these users can nevertheless navigate to Structure identifier management. This way you can also change the structure identifier descriptions in multi-user operation. In the Identifier dialog, the descriptions in the columns Structure description 1-3 and Structure description Supplementary field [1]-[10] can be edited at the same time by one user each per structure identifier. Other functionalities for editing [structure identifiers](Glossary_o_strukturkennzeichen.htm) in multi-user operation are not available and the corresponding fields and buttons grayed.

### Minimal conflict when generating connections

Updated connection information is often required when working in the graphical editor. In the Project data menu, the menu item Connections > Update is available for this purpose.

In multi-user operation it only creates a conflict if two users are updating the same [connections](Glossary_o_verbindungen.htm) or pages for the same project simultaneously. The user who started second will be informed in EPLAN by the Multi-user conflict dialog. In order to display the connection changes correctly, the user must then regenerate the connections.

In the following cases there is no conflict:

- A user updates the connections for a page (or for the entire project) while another user simultaneously edits a device placed on the same page.
- A user updates the connections for one or more pages of a project while another user simultaneously updates the connections for other pages of the project.

### Undoing actions

In multi-user operation, every user can only undo their own actions. If a user, after a change by the first user, changes the same object, the first user can no longer undo their actions.

If the first user attempts to undo their actions anyhow, the user receives a message that the changes can't be undone because another user has changed the object further.

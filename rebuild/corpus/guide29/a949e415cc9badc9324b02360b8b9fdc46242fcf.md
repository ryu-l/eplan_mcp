# Terminals

Terminals are used to [create](Glossary_o_erstellen.htm) various [connections](Glossary_o_verbindungen.htm). Differing requirements dictate a range of types, [functions](Glossary_o_funktionen.htm), and terminal [properties](Glossary_o_eigenschaften.htm).

You have the following options when working with terminals:

- You can [generate](Glossary_o_erzeugen.htm) terminals and terminal strips with the default properties from a selection of [function definitions](Glossary_o_funktionsdefinitionen.htm) that all contain common terminal types.
- Terminals can exist without terminal strips and vice-versa.
- Terminals can be managed as [main terminals](Glossary_o_hauptklemmen.htm) or auxiliary terminals. This means that terminals which consist of several functions, for example, can be represented (several separate terminals in one housing).
- Up to 50 parts can be assigned to each terminal and terminal strip.
- The terminal parts of the terminals lined up on the terminal strip can be stored at the individual terminals if they have been defined as main terminals.
- You can number terminals and terminal strips as well as create numbering [schemes](Glossary_o_schemata.htm) for the terminal designation.
- A variety of sorting options are available for positioning the terminals on the terminal strip.
- Terminals can be connected using jumpers. A variety of jumper types are available for this, which can be either automatically generated or manually created.
- Each terminal can administer 32 [wiring](Glossary_o_verdrahtungen.htm) and jumper targets.
- You can specify different potential types for terminals.
- EPLAN allows you to manage multi-level terminals. You can specify the number of [levels](Glossary_o_etagen.htm) of multi-level terminals.
- Terminal connections can be shown distributed with the help of [distributed terminals](Glossary_o_teilklemmen.htm).
- Terminal strips can also be imported or exported.

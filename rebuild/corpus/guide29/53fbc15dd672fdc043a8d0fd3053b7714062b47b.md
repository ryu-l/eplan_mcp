# Parts Management: Identifiers for Importing and Exporting Data

In the internal parts database, components, [modules](Glossary_o_module.htm), and [assemblies](Glossary_o_baugruppen.htm) can be grouped into different [product groups](Glossary_o_produktgruppen.htm) and subgroups. The parts number is still unique over all [trades](Glossary_o_gewerke.htm) and generic product groups.

The generic product group, the product group, and the product subgroup each have the [settings](Glossary_o_einstellungen.htm) options "Invalid" (code "-1") and "Undefined" (code "0"). These are particularly important when a parts import fails or does not supply appropriate information.

The following [record types](Glossary_o_datensatztypen.htm) are available:

| Record type | Class code |
| --- | --- |
| Part: Undefined | 0 |
| Part: Component | 1 |
| Part: Assembly | 4 |
| Part: Module | 5 |
| Drilling pattern | 6 |
| Connection point pattern | 7 |
| Customer | 11 |
| Manufacturer / supplier | 12 |

The record type must be specified the CSV field "class". Otherwise this information is lost! (The field is stored in the "tblPart" table of he corresponding csv file. Detailed information is available in the help topic "[Parts management: CSV Import and Export for Parts](partsmanagementgui_k_konfigurationcsvartikel.htm)".)

In addition a Trade can be specified for all the parts in the General tab. This is taken into consideration during the data transfer as follows: If the check box for the trade is activated, the identifier "1" is applied. If the check box is not activated, identifier "0".

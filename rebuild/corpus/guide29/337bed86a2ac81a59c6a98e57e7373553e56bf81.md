# Reorganizing Projects

When you reorganize a project, then deleted data is irretrievably removed from the project database. The project database is reduced in size.

Precondition:

You have selected a project in the page navigator or in the Project management dialog.

1. In the page navigator, select the Project > Organize > Reorganize menu [items](Glossary_o_bauteile.htm) or in the project management select [Organize] > Reorganize.
2. In the Reorganize project dialog, leave the Advanced mode check box deactivated and click [OK].  
     
   ![](../Pictures/Gui/ALL/arrow.png) The project is reorganized.

### Correct project data structures

For reorganization, an advanced mode is available. This mode allows for automatic correction of field length excesses in the project database as well as for internal checks of the sorting IDs of the [project structure](Glossary_o_projektstruktur.htm) and their automatic correction, if necessary.

Field length excesses can result from entering very long identifiers, numbers, and [designations](Glossary_o_bezeichnungen.htm). the cause for this being that most database fields of the project database have a length limit. A field length excess can lead to truncating the entered data. This may lead to incorrect results.

Precondition:

You have selected a project in the page navigator or in the Project management dialog.

1. In the page navigator, select the Project > Organize > Reorganize menu items or in the project management select [Organize] > Reorganize.
2. In the Reorganize project dialog, activate the Advanced mode check box.
3. Click [OK].  
     
   ![](../Pictures/Gui/ALL/arrow.png) The project is reorganized.  
     
   ![](../Pictures/Gui/ALL/arrow.png) Parts that exist double in the project are removed. The [connections](Glossary_o_verbindungen.htm) are deleted and subsequently generated again and optimized.  
     
   ![](../Pictures/Gui/ALL/arrow.png) In addition, the project database is searched for field length excesses. If a field length excess is discovered, the database is restructured so that the field length of the respective database field is adjusted in accordance with the entered data length (plus a 10 percent reserve). Then, the new field length is stored in the project.

# Spare Items

To design higher level [functions](Glossary_o_funktionen.htm), electronic [devices](Glossary_o_betriebsmittel.htm) are connected to each other. These devices have physical [properties](Glossary_o_eigenschaften.htm) that are specified by the manufacturer and must be accounted for by the designer.

As a designer, you either work with [device definitions](Glossary_o_geraetedefinitionen.htm) whose [symbols](Glossary_o_symbole.htm) are then used graphically, or you design the required schematic and select the devices later. Every possible combination of these approaches is possible.

When editing device definitions, EPLAN checks and informs you if the appropriate device has changed so much in the process that it no longer conforms to the manufacturers specifications. Since there also many devices composed of different parts, as a user you can only decide on the correct device definition (combination of parts).

![](../Pictures/Gui/ALL/example.png)[![Closed](../../Skins/Default/Stylesheets/Images/transparent.gif)Example:](javascript:void(0);)

The device "auxiliary contact with 1 NO contact and 1 NC contact" is selected. If a contactor coil and and one NO contact is drawn into the schematic then everything is correct and the device functions. There is an NC contact that is not required (this contact is free, i.e. unplaced).  
 If however a contactor coil with two NO contacts is drawn into the schematic then the device definition is faulty: In the schematic, one NO contact is used that is not physically present.

There are several ways of dealing with such cases :

- EPLAN displays an error that must be corrected.
- EPLAN does not allow this situation to occur.
- EPLAN only allows this situation to occur after querying the user.

In order to recognize this type of error, EPLAN must know the correct device specification. For this reason it is possible to [create](Glossary_o_erstellen.htm) a function pool for a device. (Whether these functions are placed or not is irrelevant). A verifiable function pool can only be realized using device selection. Only when a device definition has been assigned, can [unplaced functions](Glossary_o_nicht_platziertefunktionen.htm) be checked for errors and then a message generated about them.

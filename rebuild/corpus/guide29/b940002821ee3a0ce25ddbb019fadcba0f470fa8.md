# Behavior of Shields

Shields can only be defined graphically. On a connection it is impossible to specify the shield that surrounds it.

Shields must not necessarily be named. However, it is necessary to assign a name if you draw distributed [shields](Glossary_o_abschirmungen.htm) or would like to use non-connected shields.

Unshielded [connections](Glossary_o_verbindungen.htm) can superimpose a function template with a shield.

### Unnamed shields

Shields can be used in a project without names. In this case, however, it is necessary for a [cable](Glossary_o_kabel.htm) definition line to intersect the connection connected to the shield.

![](../Pictures/Gui/ALL/example.png)[![Closed](../../Skins/Default/Stylesheets/Images/transparent.gif)Example:](javascript:void(0);)

Here, the connection attached to the shield receives the DT W5 of the cable through the cable definition line.

![](../Pictures/Visualisation/ALL/cablegui_unnamedshielding_av.png)

![](../Pictures/Gui/ALL/note.png)Note:

If multiple shields are defined only graphically and don't have shield names, EPLAN can not differentiate them at first. The organization of shields is only detected after a one-time assignment of the [cable connections](Glossary_o_kabelverbindungen.htm) in the Edit cable dialog. In doing so, the cable connections are first assigned without consideration of shields, but the shields will be given the names from the [part](Glossary_o_artikel.htm). Then the Edit cable dialog is opened again and the cable connections reassigned. Because the shields now have names, EPLAN can recognize how they are organized and correctly assign the cable connections with the shields in mind.

### External shields

If a shield connected on both sides has the representation type "External", then the shielded cable connection becomes an external connection. This is independent of the representation type of the [functions](Glossary_o_funktionen.htm) connected. Such a connection is not shown in the connections navigator.

### Definition of shields in parts management

Shields should not be defined as their own [function templates](Glossary_o_funktionsschablonen.htm) in the parts management, but rather implicitly using the connections of the [cable part](Glossary_o_kabelartikel.htm). If the part has a function template with the function definition "Conductor / wire" and the potential type "SH", a shield is generated automatically when the Insert > Device action is used before this part connection is inserted. The shield name is taken from the Color / no. field of this connection. During the Device selection a function template is generated for the shield and the data of this function template is assigned to the shield designated in the schematic.

### Shields at automatically generated cables

Existing cables are not separated during the automatic generation. If a different DT is entered at the shield than at the associated shield connection (i.e. at the connection at which the shield is applied), the shield uses the DT of the applied shield connection.

![](../Pictures/Gui/ALL/example.png)[![Closed](../../Skins/Default/Stylesheets/Images/transparent.gif)Example:](javascript:void(0);)

The DT W8 is entered at the shield. However, the shield connection has the DT W7 assigned to it through the cable definition line. After the automatic cable generation, the DT W7 of the shield connection is also transferred to the shield.

![](../Pictures/Visualisation/ALL/cablegui_repairedshielding1_av.png)

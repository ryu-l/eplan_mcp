# Extension of Pre-planning with Graphical Representations and P&I Diagrams

To be able to expand an existing pre-planning with graphical representations or P&I diagrams, you have the option at all [segments](Glossary_o_segmente.htm) to store a window macro with graphical pre-planning or [P&I diagram](Glossary_o_ri_fliessbild.htm) sections.

To this purpose the property Macro for pre-planning and P&I diagram ([ID](Glossary_o_id.htm) 44084) is available on the first tab in the [property dialog](Glossary_o_eigenschaftendialog.htm). If a window macro with the "Pre-planning" and / or "P&I diagram" representation type is selected for the property, you can place this segment with the [cut-outs](Glossary_o_durchbrueche.htm) existing in the window macro via drag & drop on a project page of the corresponding page type.

Certain requirements must be met at such an action so that the structures existing in the macro can be assigned to the structures existing in the project:

- Graphical pre-planning:   
  For the segment to be placed, a corresponding segment must be available at the highest position in the structure of the window macro (at least the same basic segment definition).

![](../Pictures/Gui/ALL/note.png)Note:

Newly placed segments are created for subordinate segments that only exist in the window macro. Subordinate segments that only exist in the project are not placed.

- P&I diagram:   
  For the segment to be placed, a corresponding segment must exist in the structure of the window macro on the same hierarchy level (same basic segment definition) and the subordinate [part](Glossary_o_artikel.htm) structures must be the same. If this is the case, the structures from the macro are automatically sorted into the pre-planning structure of the project in the Project field of the subsequent dialog Select structure.

![](../Pictures/Gui/ALL/note.png)Note:

If the subordinate part structures for the segment at which the macro is stored are not the same as the subordinate part structures in the window macro, the structures from the macro are sorted into the existing pre-planning segments but new segments are created. These are identified by the icon ![](../Pictures/Gui/ALL/all_statusnew_as.png).

If the segment at which the macro is stored and the top segment in the macro have different basic [segment definitions](Glossary_o_segmentdefinitionen.htm), an automatic assignment into the structure of the project is not possible in the dialog [Select structure](planninggui_d_strukturauswahl.htm) and all segments have to be manually sorted.

### Use of the macro when placing via drag & drop

During the drag & drop into the page navigator for creating the detail planning, the window macro selected for the Macro for pre-planning and P&I diagram property is ignored and - in as far as available - the macro stored in the Macro tab is used.

During the drag & drop into the a pre-planning page or a P&I diagram page, the window macro selected for the Macro for pre-planning and P&I diagram property is used, even if a further macro is stored in the Macro tab. As a prerequisite the respective window macro must contain the representation type "Pre-planning" and/or "P&I diagram".

![](../Pictures/Gui/ALL/info.png)Tip:

We recommend that you mainly store [macros](Glossary_o_makros.htm) in the Macro tab that you use for the creation in the detail planning, while you enter [window macros](Glossary_o_fenstermakros.htm) that you use for the extension of the graphical pre-planning or the P&I diagram into the property Macro for pre-planning and P&I diagram.

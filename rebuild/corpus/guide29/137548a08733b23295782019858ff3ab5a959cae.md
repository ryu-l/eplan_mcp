# Storing Subprojects

In order to store subprojects mark the desired filed-off subprojects in the dialog Subprojects and click the [Store] button. Multiple selection of filed-off subprojects is possible.

During storing the pages, layout spaces and pre-planning [segments](Glossary_o_segmente.htm) are copied from the respective subproject 1:1 into the original project. In the process the respective [objects](Glossary_o_objekte.htm) (pages, layout spaces, etc.) in the original project are overwritten, the external [cross-references](Glossary_o_querverweise.htm) removed and the change protection for the respective defined working section removed. The subproject number as the editor of a defined working section is removed in the dialogs for the defined working sections. The subproject as such no longer exists after storing.

![](../Pictures/Gui/ALL/note.png)Note:

If the protected defined working section was changed in the original project or if pages, layout spaces or pre-planning segments outside this defined working section were created in the subproject, a corresponding prompt is displayed whether the subproject should be stored nevertheless. At the same time module-specific [check run messages](Glossary_o_prueflaufmeldungen.htm) are created in the message management. This allows you to stop storing and branch to the causing objects (pages, layout spaces, etc.) by means of the message management.

After a subproject has been stored, you may have to still correct the sorting of the [structure identifiers](Glossary_o_strukturkennzeichen.htm) and update or [create](Glossary_o_erstellen.htm) the [reports](Glossary_o_auswertungen.htm). Subsequently subprojects can again be generated and edited externally in the course of further editing by external [editors](Glossary_o_editoren.htm).

# Network drives under Windows Vista and Windows 7

The User Account Control UAC introduced with Windows Vista may cause problems for the client-server installation if the resources are on a network drive. For a description of the technical background, see the Microsoft Knowledge Base article no. 937624 at <http://support.microsoft.com/kb/937624/en-us>.

In summary, problems occur if the following conditions apply:

1. The User Account Control is active.
2. During the installation, a path to a network drive is to be selected.
3. The network drive is connected only for this Windows session, i.e., it is not persistent. This is the case if, during the connection of the network drive by means of the graphical interface, the check box Reconnect at logon is not selected, or if during the connection by means of net use, the option /persistent:no has been selected, which is the default.
4. In the setup wizard, you are to navigate to the connected drive via [Browse...].

The drive is not visible in this case.

Problem troubleshooting solutions are:

Solution 1: Establish permanent connection for the network drive.

1. Open Windows Explorer
2. Disconnect the network drive if already connected.
3. In the menu Extras > Connect network drive, open the wizard for connecting network drives.
4. Select check box Restore connection at logon.
5. Enter all data, and confirm with [OK].

Solution 2: Connecting the drive in the administrator context

1. Open the context menu for the Start menu entry All Programs > Accessories > Command Prompt.
2. Select Run as Administrator.
3. Confirm the prompt.
4. Connect the drive via net use <drive> <UAC path> </user:login>.

Solution 3: Wrong path input and subsequent repair.

1. On the setup wizard page that prompts for the folders of the resources, input an incorrect path, e.g., C:\temp.
2. Change the information after the installation in the ec.ini file in the local installation folder on the client.
3. The information is entered in the ec.ini line as -Dcom.mind8.global.resourcePath=<Path>.
